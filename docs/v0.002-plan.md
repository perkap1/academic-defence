# Academic Defence v0.002 – design og implementeringsplan

> Gjennomføres direkte i det eksisterende prosjektet med superpowers:executing-plans. Brukeren har bedt om en ferdig, lokalt testbar webversjon.

## Design

Bevar bane 1, ni byggeplasser, Book Tower, økonomi og kunnskapssystem. Utvid den eksisterende studentkomponenten med type og kjønn, og bygg Blackboard Tower som en egen tårnscene. Bruk en direkte undervisningspuls mot nærmeste students posisjon: rekkevidde 225, område 105, 15 kunnskap per student, intervall 1,3 sekunder og pris 100. Book Tower beholder pris 70, rekkevidde 260, intervall 1 og 20 kunnskap.

PE-studenter bruker gutt/jente tilfeldig, hastighet 114,75 (35 prosent raskere), samme 100 kunnskap og samme rute. Sprite-rammer normaliseres i grupper med én felles skalering og fot-/sokkelanker; animasjoner endrer aldri selve enhetens plassering. Bølgene blir 4, 6, 8, 11, 14, 17 og 20 studenter, med henholdsvis 0, 0, 2, 3, 4, 5 og 6 PE-studenter.

En tom byggeplass åpner et panel som viser begge tårn, pris, informasjon og faktisk deaktivert knapp når det mangler gull. UI-rammer og ikoner fra vedleggene brukes i HUD, byggemeny, verktøytips og handlingsknapper. Pause stopper gameplay mens UI fortsetter å virke. Ingen hurtigspoling eller nye oppgraderinger i denne versjonen.

World Map er startscenen. Den venstre noden åpner eksisterende bane 1. De fire øvrige nodene viser lås og kan ikke starte noe. Spiller kan gå tilbake til kartet fra banen eller resultatet, eller starte banen på nytt.

Web eksporteres med Godot 4.4.1, kompatibilitetsrenderer og uten trådkrav. En lokal server bindes kun til 127.0.0.1 og gir en klikkbar lenke. Ingen offentlig publisering.

## Oppgaver og tester

1. Assets: trekk ut UI, ikoner, Blackboard-frames og PE-frames med stabile ankere. Bevar de nye originalsheets som kildeassets. Hent offisielle webmaler for eksisterende Godot-versjon.
2. Tårn: utvid GameManager.try_build(slot, tower_type) med pris 70/100 og BlackboardScene; test gull, avvist type/dobbeltbygging og puls som treffer gruppe innen radius uten å treffe utenfor.
3. Student og bølger: Student.configure(type, variant) før add_child; test hastighet, begge kjønn, kunnskapsbar, frame-stabilitet og riktig PE-fordeling i alle sju bølger.
4. UI: klikk på plass åpner byggemeny; valg sender build_requested(slot, type); test begge byggetyper, utilstrekkelig gull, pause/gjenoppta og omstart med faktiske klikk.
5. WorldMap: fem noder, én åpen; test oppstart, avvist låst node, overgang til Main og retur.
6. Spillrunde: oppdater og kjør eksisterende regel-/integrasjonstester samt nye v0.002-tester; vinnbar blandet tårnstrategi, tap, korrekt antall studenter, stopp ved tidlig tap og ren omstart.
7. Web: importer, eksporter via Godot, start lokal server, åpne nettleser og test World Map → bane → byggemeny → gameplay. Kontroller grafisk UI og artefakter; pakk prosjekt og webversjon, dokumenter endelige testresultater.

## Review focus

- Frame-boundingbokser med gnister må ikke endre tårnets sokkel eller studentenes føtter.
- Puls må håndtere studenter som fullføres og fjernes midt i gjennomgangen.
- Menyvalg må kontrollere at valgt plass fortsatt er ledig og at prisen kan betales.
- Pause må kunne oppheves fra UI og må nullstilles ved sceneovergang.
- World Map-låser og webinput må fungere i den faktisk eksporterte versjonen.
